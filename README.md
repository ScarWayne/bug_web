# BREW LAB — QA training landing

> Современный одностраничный лендинг мини-магазина specialty-кофе
> с переключением **RU/EN**, формами, корзиной, чекаутом, калькулятором
> и **35 преднамеренными дефектами** для практики QA-тестирования. 
>
> Полный список дефектов с шагами воспроизведения — в [`BUGS.md`](./BUGS.md).

## Стек

- HTML5 (canonical), современный CSS:
  - `oklch()` colors, CSS Grid, container queries (`@container`),
    `:has()`, view transitions, `@starting-style`-friendly разметка
- ES2022 vanilla JS (без сборщика — открывается «как есть»)
- Шрифты: Instrument Serif · Geist · JetBrains Mono (Google Fonts)
- Никаких бэкенд-зависимостей — статический сайт, идеально для GitHub Pages

## Локальный запуск

```bash
# любой статический сервер, например:
python3 -m http.server 8080
# или
npx serve .
```

Открыть `http://localhost:8080`.

> Открыть `index.html` напрямую через `file://` тоже работает,
> кроме Google Fonts (нужен сетевой доступ).

## Деплой на GitHub Pages

1. Создать репозиторий, запушить содержимое этой папки в `main`.
2. **Settings → Pages → Build and deployment → Source: `Deploy from a branch`**.
3. Branch: `main`, folder: `/ (root)` → **Save**.
4. Через ~1 минуту сайт будет доступен на
   `https://<user>.github.io/<repo>/`.

Все ассеты — относительные, никаких настроек путей делать не нужно.

## Что внутри (тренировочные зоны для QA)

- **Hero + статистика** — типографика, переключение языка
- **Features (6 карточек)** — container queries, hover-состояния
- **Магазин (6 SKU)** — добавление в корзину, бейджи NEW/RARE/TOP
- **Тарифы / подписка (3 уровня)** — выбор тарифа в корзину
- **Калькулятор** — ползунки чашек/грамм + сегментированный выбор
  способа заваривания и тарифа
- **FAQ** — `<details>`-аккордеон
- **Newsletter** — email-подписка
- **Контакт-форма** — имя/телефон/сообщение
- **Регистрация** — email + индикатор силы пароля + подтверждение
- **Корзина** — qty, купоны, итог
- **Чекаут** — ФИО/email/телефон/адрес/город/индекс/карта/MM-YY/CVV
- **Футер** — соцссылки, юр. документы

## Как пользоваться как тренажёром

1. Прочитайте только этот README.
2. Пройдитесь по сайту с чек-листом (UI / валидация / логика / безопасность
   / a11y / perf / i18n / state).
3. Запишите найденные баги в свой багтрекер.
4. Сравните результат с `BUGS.md`.

## Используемые «фичи безопасности» (имитация — клиентская)

- CSP-meta тег
- honeypot-поле в форме подписки
- ограничения по `maxlength` в большинстве полей
- индикатор силы пароля
- экранирование вывода (включено НЕ везде — это часть учебного материала)
